How to vet a template before you run it (the checklist)

A template is someone else's code running with your credentials. Treat it accordingly:

  • Open every HTTP Request node and read the URL. It should point only at services you recognize.
  • Read every Code node. You're looking for anything that sends data somewhere unexpected. Paste it into Claude and ask "does this transmit data externally?" if you can't read JavaScript.
  • Strip embedded credentials and IDs — sheet IDs, webhook URLs, API keys — and replace with your own.
  • Run manually against test data first. A dummy row, a test inbox. Only activate the trigger after a clean manual run.
  • Pin it to a version. Note which n8n version it worked on; community nodes can lag core upgrades.

FAQ

Where are the best free n8n templates?

n8n.io/workflows for browsing, the Zie619 GitHub repo for coverage, curated practitioner packs for quality. Start with a tested pack of five, not a library of two thousand.

Why doesn't my imported template work?

Ninety percent of the time: credentials not connected, node versions outdated, or hardcoded IDs still pointing at the author's accounts. Work through the vetting checklist above — it doubles as a debugging checklist.

Can I sell workflows I build from free templates?

Generally yes — configured, deployed instances of open workflows are exactly what clients pay for. They're not buying JSON; they're buying it running reliably against their systems. That business model is the subject of how to sell AI automation services.
